# Episode 03: Master System Roles & Temperature Controls

In this lecture, the focus shifts from basic API calls to controlling **LLM Behavior** and **Creativity**. As an AI engineer, you don't just prompt a model; you program its **identity (System Role)** and its **probabilistic output behavior (Temperature)**.

## 1. High-Level Real-World Analogies

To understand why these parameters exist, consider two real-world scenarios:

### Analogy A: The "I Love You" Test (System Role / Context)

* If you say *"I love you"* to your romantic partner, the expected response is *"I love you too."*
* If you say *"I love you"* to your corporate manager or college professor, the outcome could be an HR complaint or legal action.
* **Takeaway:** The exact same input text (`user` prompt) yields vastly different responses depending on the **relationship and persona** defined prior to the message.

### Analogy B: Exam Advice from 3 Types of Friends (Temperature / Personality)

If you ask three different friends *"How do I score good marks in exams?"*:

1. **The Safe/Standard Friend:** Answers *"Study hard and revise properly."* (Deterministic, low-risk).
2. **The Creative Friend:** Answers *"Focus only on important previous-year questions and memory tricks."* (Moderate variance).
3. **The Unhinged Friend:** Answers *"Kidnap the professor or forge the answer key."* (Extreme risk/randomness).

* **Takeaway:** The query remains identical, but the **risk tolerance and creativity** of the responder dictate the output.

## 2. Topic 1: System Role (`system`)

In standard LLM completions, messages are structured inside an array of dictionaries. While `user` and `assistant` represent the conversation history, the `system` role sets the **operating rules** for the model.

```
[ System Message: Define Persona & Rules ] 
                   ↓
[ User Message: Input Prompt ] ---> [ LLM Engine ] ---> [ Assistant Response ]

```

### Roles in the Message Payload

* **`user`**: The raw prompt/query supplied by the end-user.
* **`assistant`**: The response generated by the LLM (or past model responses in a chat history).
* **`system`**: High-priority instructions passed at the beginning of a completion array to define identity, constraints, tone, and operational boundaries.

### Production Engineering Use Case: Multi-Agent Architectures

When an enterprise purchases access to a foundation model API (e.g., Groq, OpenAI, Anthropic), they do not create different AI models for different tasks. Instead, they instantiate multiple **AI Agents** from the same model endpoint using distinct **System Roles**:

1. **Senior Software Architect Agent:**
* `system`: `"You are a Senior System Architect. Evaluate all code for scalability, security vulnerabilities, memory leaks, and maintainability."`


2. **Junior Developer Agent:**
* `system`: `"You are a Junior Developer. Focus on writing clean functions, resolving syntax bugs, and writing unit tests for localized code."`


3. **QA Engineer Agent:**
* `system`: `"You are a QA Lead. Analyze user requests strictly for edge cases, missing assertions, and boundary failures."`

## 3. Topic 2: Temperature (`temperature`)

### How LLMs Work Under the Hood

LLMs are **not truth-telling search databases**; they are **probabilistic token prediction engines**. Given a sequence of input tokens, the model calculates a probability distribution across its vocabulary for the next most likely token.

> **Analogy:** If a toddler is taught only the days of the week ("Sunday, Monday"), when prompted with "Sunday, Monday...", she predicts "Tuesday". If prompted with "January, February...", she might still say "Friday" because days of the week are all her prediction model knows.

### Defining Temperature

The `temperature` parameter modifies the probability distribution curve before selecting the next token:

$$\text{Probability Distribution Adjustment} \implies \text{Higher Temp} = \text{Flatter Distribution (More Random)}$$

| Temperature Value | Behavior | Output Characteristics | Best Use Cases |
| --- | --- | --- | --- |
| **`0.0` (Deterministic)** | Picks the highest-probability tokens. Safe & predictable. | Factual, direct, repeatable, low variance. | Medical diagnosis, code generation, legal contract parsing, math/logic. |
| **`0.7` - `1.0` (Balanced)** | Introduces moderate randomness while remaining coherent. | Natural conversation, balanced storytelling. | Chatbots, summary writing, email drafting. |
| **`1.5` - `2.0` (High Randomness)** | Picks lower-probability tokens. Highly creative or abstract. | Novel combinations, wild ideas, higher risk of hallucination. | Brainstorming brand names, fiction writing, poem generation. |

### Brand Name Generation Example

If you ask the model to generate a name for a new Food Delivery application:

* **`temperature = 0.0`**: Suggests *"Food Express"* or *"Dhaba"* (Literal, safe, most common associations).
* **`temperature = 1.0`**: Suggests *"Zomato"* (Creative variation derived from "Tomato").
* **`temperature = 2.0`**: Suggests *"Swiggy"* (Completely novel, abstract, unconstrained branding word).

> **Note:** Setting `temperature` beyond the supported API bounds (e.g., `3.0`) will trigger a validation error from provider SDKs (Groq/OpenAI limit range typically between `0.0` and `2.0`).

## 4. End-to-End Code Walkthrough

Below is the complete Python script illustrating how to combine `system` roles and `temperature` controls using the `groq` or `openai` SDK inside a virtual environment.

### Project Setup

```bash
# 1. Initialize project directory using uv
uv init week_1/day_2
cd week_1/day_2

# 2. Create and activate virtual environment
uv venv --python 3.11
source .venv/bin/activate  # On Windows: .venv\Scripts\activate

# 3. Add required dependencies
uv add groq python-dotenv

```

### Python Script (`system_temperature.py`)

```python
import os
from pathlib import Path
from dotenv import load_dotenv
from groq import Groq

load_dotenv()
my_api_key=os.getenv("GROQ_API_KEY")

if not my_api_key:
    raise ValueError("API key kaha hai bhai")

client=Groq(api_key=my_api_key)

model="llama-3.3-70b-versatile"
role="user"
prompt="Suggest a name for my clothing company"
# SYSTEM
message_system={
    "role": "system",
    "content": "You are a brand manager who suggests name for my company. name should be in one word. suggest only one name"
}
# message me role and content
message={
    "role": role,
    "content": prompt
}

messages=[message_system, message]
# Temperature by default is 0 meaning safe. range is [0,2]
response=client.chat.completions.create(model=model, messages=messages, temperature=0)
# print(response)

print("#######################################")

answer=response.choices[0].message.content
print(answer)

```

## 5. Summary Cheat Sheet for AI Engineers

1. **Order Matters:** Place `{"role": "system", ...}` as the **first element** in the `messages` array so the model initializes its runtime context before reading user inputs.
2. **Deterministic Tasks:** Use `temperature=0.0` for JSON generation, SQL querying, code writing, and medical/legal parsing.
3. **Creative Tasks:** Use `temperature=0.8` to `1.5` for slogan generation, creative writing, and multi-agent brainstorming.
4. **Error Handling:** Avoid setting `temperature` values outside `0.0 - 2.0`. Always catch package loading errors and check your terminal commands carefully (e.g., `uv add groq python-dotenv`).
